SOMNIUM — CURRENT PROJECT STATE
Last updated: November 9, 2026
Current baseline: Geometry Phase 17I — Bidirectional Spherical Anomaly Passage

1. PROJECT OVERVIEW

Somnium is a browser-based Babylon.js world simulation with an extensible spatial architecture. Its geometry system represents ordinary worlds as independent three-dimensional WorldSlices embedded in an ambient four-dimensional R4 space. Explicit anomaly topology connects selected slices. Ordinary gameplay is three-dimensional; anomaly influence fields can expose movement along the fourth spatial axis.

Rendering projections are derived views. Authoritative positions, slice frames, geometry, metrics, chunk identities, and optical paths remain independent of render-space coordinates.

2. CURRENT GEOMETRY ARCHITECTURE

- WorldSlice provides stable identity, geometry type, revision, and an orthonormal 4D frame.
- WorldTopology stores explicit slice/anomaly relationships, with independent player-traversal and optical-connectivity permissions.
- SpatialChunkGraph preserves 3D chunk addresses: (sliceId, chunkX, chunkZ). Anomaly chunks remain explicit graph nodes.
- SpatialTransform owns intrinsic slice metrics and world/render projection.
- Slice-transition anomalies use bounded ambient 4D regions and continuous smootherstep influence fields.
- Player W movement and optical W propagation have independent permissions and coefficients.
- The legacy cubic Bezier corridor implementation remains available.

3. COMPLETED GEOMETRY MILESTONES

Phases 1–15 established the 4D world-slice architecture, chunk/topology relationships, slice-transition anomalies, four-axis anomaly traversal, the rotating tesseract chamber, Poincare chart safety, camera refinements, Main World re-entry, and the metric-grid visualization.

Phase 16A — Optical Mathematics and CPU Reference Solver:
- Versioned optical material and anomaly-permission contracts.
- Ambient R4 optical metric/cometric construction.
- Independent optical W coupling using the anomaly radial envelope.
- Adaptive CPU Hamiltonian ray integration and deterministic diagnostics.
- Scale-relative positive-definite matrix validation for small physical metric tensors.
- Explicit metric-domain guards and controlled chart-boundary termination.

Phase 16B — Slice-Native Ray Paths and Intersections:
- Scene-scoped OpticalSceneRegistry.
- Deterministic per-registration triangle BVHs with slice/chunk identity.
- Analytic streamed-terrain heightfield intersection.
- Babylon geometry adapter that registers authoritative geometry before nonlinear visual projection.
- Euclidean and Poincare slice-native ray tracing.
- Render-space-only debug ray visualization.

Phase 16C — Cross-Slice Anomaly Optical Transport:
- Independent optically-enabled topology edges; player traversal permission is not consulted.
- Anomaly-specific optical W reach, W coupling, aperture radius, refractive index, attenuation, transmission, directionality, and entry bias.
- Stable endpoint-sampled blend of the source/destination slice tangent metrics in the anomaly bridge; pointwise chart sampling remains opt-in.
- True ambient R4 Hamiltonian propagation inside bounded slice-transition anomaly regions.
- Aperture entry/exit event detection, with interface transfer preserving aperture-tangential canonical momentum and the Hamiltonian constraint.
- Optical chunk reachability checks before entering and exiting an anomaly.
- Multi-anomaly path traversal with explicit transition and segment limits.
- Controlled `chart-domain-boundary` ray events for finite Poincare metric domains.
- All three demo anomaly connections are optically enabled in both configured directions.

Phase 16D — View-Dependent Anomaly Aperture Rendering:
- Replaces the fixed remote preview-camera pose with a view camera transported through the anomaly's endpoint-frame correspondence.
- The mapped remote camera updates from the active viewer's current position, forward direction, and up vector.
- The direct Hypercube-to-Main-World demo aperture is a circular render surface rather than a square/rectangular preview plane.
- Adds an anomaly `view` contract, independent of player traversal and optical ray permissions, with endpoint-frame/static mapping, circle/ellipse/rectangle shapes, and constant/Euclidean-4D-ball cross-section profiles.
- A Euclidean 4D spherical aperture's 3D section uses `sqrt(R² - d²)` and is hidden after its section radius reaches zero.
- Destination chunk focus follows the mapped remote camera direction/position; portal diagnostics expose camera pose, shape, scale, and remote render-list size.
- Existing world lighting and atmospheric response are intentionally unchanged. Optional anomaly-driven sky glow is deferred as an artistic feature.


Phase 17A — Movable Anomaly-Fed Spotlight Prototype:
- Adds an engine-independent, validated spotlight source contract in slice-local coordinates.
- Places a visible, editable spotlight in the Hypercube chamber, with separate XYZ movement and yaw/pitch controls.
- Traces a deterministic central ray through only the explicitly selected Hypercube-to-Main-World optical anomaly.
- Stops the optical trace at the first successful anomaly exit when a receiver needs the outgoing state, avoiding an unnecessary long destination-slice tail.
- Derives a destination-slice virtual spotlight from the outgoing aperture position and canonical momentum, then converts its position and direction through the Main World SpatialTransform.
- Creates a receiving-side Babylon spotlight and a bounded shadow map with nearby Main World terrain and scene meshes; caster membership is refreshed as streamed geometry changes.
- Adds trace, receiver, and shadow-caster diagnostics.
- Preserves existing scene lighting and leaves point lights, multiple light sources, soft-shadow sampling, and fully per-surface optical shadow rays for later increments.

Phase 17B — Main World Optical Ray and Portal Readability:
- Adds the receiving-side optical ray to the destination portal preview render lists.
- Improves the direct Main World anomaly display size and spacing as a presentation-only adjustment.
- Keeps canonical anomaly endpoints separate from displayed portal positions.

Phase 17C — Main World Re-entry and Light Controls:
- Adds an explicit mapping between displayed Main World portal positions and canonical anomaly endpoint positions.
- Applies the mapping consistently to anomaly entry/re-entry, slice activation, chunk reachability, and portal preview presentation.
- Adds independent light-edit and test-ray controls.

Phase 17D — Open 4D Hypercube Boundary:
- Renders six 3D side cells of an open 4D hypercube boundary, with both W-facing end cells omitted.
- Updates the displayed boundary from the active W-slice while leaving traversal/collision geometry unchanged.
- Adds clickable light-edit and test-ray HUD controls synchronized with their keyboard shortcuts.

Phase 17E — Tapered 4D Cylinder Boundary:
- Replaces the demo open-hypercube boundary with a W-aligned 4D cylinder.
- Renders its 3D spherical cross-section in each active W-slice.
- Uses endpoint radii and quintic smootherstep interpolation to make the section expand from the Hypercube side toward the Main World.

Phase 17F — Destination Approach and Mouth Continuity:
- Progressively converges the destination preview camera toward the far anomaly endpoint while preserving screen-up clearance.
- Establishes diagnostics for approach progress and mapped remote camera position.
- Its additional portal-mesh aperture scale curve is superseded in Phase 17G for tapered cylinders because it competed with the live cylinder cross-section and could create a visible reversal at endpoint handoff.

Phase 17G — Spherical Anomaly Mouth and Stable Cylinder Aperture:
- Makes the tapered cylinder boundary the single source of mouth-diameter progression; the preview surface scale stays fixed at its authored endpoint size across forward/reverse transit and endpoint handoff.
- Phase 17G historically introduced the optional shallow spherical-cap preview. Phase 17H supersedes that preview path with a complete closed sphere; the legacy cap deformation helper remains exported for compatibility.
- The flat disc remains available with `previewSurface: 'flat'`.
- Removes the legacy torus mouth rim by default. `showRim: true` remains an explicit compatibility opt-in.
- Keeps canonical anomaly endpoints, traversal, optical transport, and the underlying destination world unchanged.

Phase 17H — Complete Destination Sphere and Inner-Mouth Growth:
- Replaces the shallow spherical-cap preview with a complete closed Babylon sphere using front-orthographic destination-image UVs; the flat-disc option remains available.
- Adds a separately configurable inner destination-sphere growth curve (start scale 0.08, exponent 0.55) that grows faster than the tapered outer tube.
- Normalizes progress from the current viewer's entry endpoint and swaps endpoint radii for reverse travel; clamps the inner sphere to the current outer section and matches the far-mouth radius at the endpoint.
- Allows destination preview mesh scales greater than one where the far aperture is wider than the entry aperture.
- Leaves the outer cylinder, canonical endpoints, W-slice traversal, and anomaly editor unchanged.

Phase 17I — Bidirectional Spherical Anomaly Passage:
- Replaces the single remote-aperture transit presentation with simultaneous source entrance and destination exit mouths, each rendered as an independent complete 3D sphere.
- Places the entrance behind and the exit ahead along a configurable display-space depth axis. A stable frame is captured at transit start; the camera can orbit and translate to inspect the passage from different angles.
- Advances the presentation camera along the display axis with normalized traversal progress so perspective naturally makes the entrance appear smaller and the exit appear larger.
- Renders the starting world into the entrance mouth and the destination world into the exit mouth, reusing existing endpoint render lists and world ownership.
- Uses a dedicated rendering layer and black scene background during transit; restores ordinary scene presentation at the endpoint handoff.
- Keeps canonical 4D anomaly geometry, collision, topology, W traversal, and chunk ownership unchanged. Reverse traversal swaps endpoint roles and radii.

The scene creates one optical registry shared by the geometry demo and Main World. Resident Main World chunks register analytic heightfields and unregister them when mesh resources are disposed. Eligible demo meshes and the dynamic tesseract cross-section register slice-local triangle geometry. Scene metadata exposes the registry, stats, debug renderer, and factories for slice-native and topology-aware anomaly tracers.

The anomaly tracer uses only explicit optical topology. It traces a 3D slice segment to an aperture, transfers the ray into a bounded 4D anomaly metric, finds a reachable destination aperture, transfers the ray back into the destination slice, and may continue through another explicitly connected anomaly.

6. CURRENT LIMITATIONS / NEXT WORK

The Phase 16A–16C ray transport engine remains a CPU reference for topology-aware light propagation. It does not yet:
- Intersect arbitrary 4D mesh geometry placed inside anomaly interiors; the current 4D bridge traces the optical metric and aperture/horizon/region events.
- Render anomaly-interior R4 ray segments as a 3D/4D diagnostic visualization. Current debug rendering draws slice-native segments only; R4 samples remain available in trace results.
- Apply reflection, refraction, or total internal reflection at optical surfaces. The current aperture interface is an idealized momentum-transfer boundary, not a dielectric Fresnel/Snell model.
- Validate the aperture camera mapping, complete-sphere destination surface, front-orthographic texture projection, transparency/depth ordering, and Main World endpoint handoff in a live browser/WebGL session across camera orbit, observer movement, and both travel directions. Automated tests cover sphere geometry construction, UV projection, radius progression, camera transport, and render-target configuration, but not final visual quality.
- Implement custom anomaly-view mappings and cross-section evaluators beyond the initial endpoint-frame mapping and the constant/Euclidean-4D-ball cross-section profiles. Circle, ellipse, and rectangle aperture shapes are supported; complete-sphere and legacy spherical-cap preview surfaces support circle/ellipse only.
- Generalize the tapered 4D cylinder boundary beyond W-aligned axes and test its visible spherical cross-section under arbitrary 4D slice-frame orientations.
- Validate that the complete spherical destination preview reads as a 3D opening in the live browser, including front-orthographic UV distortion at off-axis viewpoints, nonlinear Poincare projection, and transparency/depth-sort interactions. The flat circular preview remains the fallback option.
- Consider a distinct in-tube destination aperture surface if camera parallax and the spherical mouth still do not communicate apparent destination approach convincingly. It must not add a second competing mouth-scale curve.
- Generalize from one deterministic centre-ray spotlight to multiple point/spot sources and beam sampling.
- Implement fully per-surface optical visibility/shadow rays through anomaly bridges; the initial receiver-side shadow map is a bounded virtual-light approximation.
- Implement soft shadows, multiple-bounce global illumination, or diffraction.
- Add optional anomaly-driven atmospheric glow/sky-colour response as a later artistic layer.
- Use a GPU/optimized optics backend and production ray budgets (Phase 16F).

The default anomaly bridge metric uses endpoint-sampled tangent metrics blended along the common slice normal. This avoids extrapolating a Poincare chart beyond its valid aperture domain. Pointwise endpoint-chart sampling is supported as an opt-in but will terminate cleanly at declared chart boundaries.

The interface law preserves tangential canonical momentum and solves the normal coefficient to preserve the Hamiltonian. It currently uses a deterministic aperture-normal transfer rule; later surface optics may add reflected/transmitted energy branches.

The triangle BVH is currently per mesh registration and tagged with chunk identity, rather than aggregated into one chunk-wide hierarchy. This is an intentional first implementation; Phase 16F should use profiling to decide whether chunk-level aggregation is worthwhile.

Curved ray/triangle intersection uses short chords between adaptive integration samples. The maximum integration step controls the approximation. Terrain intersections sample at density derived from the source raster's independent X/Z world spans and refine detected crossings by bisection.

A live browser/WebGL visual validation has not been completed in the automated environment. The Phase 17A receiving spotlight/shadow appearance, Phase 17H complete-sphere portal projection, and Phase 17I dual-mouth passage composition, off-axis UV behavior, render-target performance, and endpoint handoff still require manual browser validation. A dedicated anomaly-interior R4 debug display also remains future work.
