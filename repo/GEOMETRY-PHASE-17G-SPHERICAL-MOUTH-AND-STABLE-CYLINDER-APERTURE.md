# Geometry Phase 17G — Spherical Anomaly Mouth and Stable Cylinder Aperture

**Status:** Implemented; automated regression suite passes.  
**Build:** `somnium-20261109-phase17g-spherical-mouth-continuity-2`  
**Baseline:** Phase 17F destination approach and mouth continuity.

## Objective

Remove the abrupt/reversing preview-mouth scale behavior observed around the Main World W endpoint, make the selected anomaly preview surface a genuinely three-dimensional spherical opening rather than a flat circular disc, and remove the legacy decorative torus ring from the demo anomaly mouths. Preserve a selectable flat preview mode for anomaly types that need it.

This is a presentation-only milestone. It does not change canonical anomaly endpoints, the 4D region, optical permissions, traversal, cylinder taper, or the destination world geometry.

## 1. One source of truth for tapered-cylinder mouth size

Phase 17F combined two independent presentation effects for tapered cylinders:

1. the live cylinder cross-section radius, already derived from the observer's ambient W position and the source/destination endpoint radii; and
2. an additional portal preview mesh scale interpolated from the narrow-to-wide endpoint radius ratio using transit approach progress.

The second scale curve was direction-sensitive at transit boundaries. The preview could be fully scaled, then be resized again as progress was resolved or cleared during endpoint handoff. On reverse movement this could look like a size reversal, even though the cylinder's own section law was monotonic and clamped beyond its endpoint interval.

For `interiorBoundary: 'open-4d-cylinder'`, `calculateAnomalyApertureScale()` now returns `1` for every progress value and on either side of the handoff. The preview surface remains at its authored endpoint dimensions. The **tapered cylinder boundary is the only source of changing cross-section diameter**. Its radius continues to come from `buildAnomalyCylinderGeometry()` using the clamped normalized W coordinate and quintic smootherstep interpolation between `interiorBoundaryRadii.source` and `.destination`.

The destination-approach effect remains in `mapAnomalyCameraPose()`. It moves the virtual remote camera toward the destination endpoint while preserving the screen-up clearance. Camera convergence and cylinder cross-section are separate, non-competing effects.

The legacy `euclidean-4d-ball` aperture law remains in place for anomalies that do not use an open tapered 4D cylinder. This preserves earlier spherical-aperture behavior rather than globally replacing all anomaly view sizing.

## 2. Three-dimensional spherical preview surface

Anomaly view configuration now supports:

- `previewSurface: 'flat'` — existing flat Disc/Plane surface; remains the default.
- `previewSurface: 'spherical'` — a concave spherical-cap surface for circular or elliptical apertures.

The spherical cap is generated by curving the unit Disc vertices onto a spherical surface. Its rim remains at the authored aperture plane and its centre recedes away from the viewer, creating a visible bowl-like 3D mouth. The render-target UV coordinates are preserved, so the destination camera image remains a normal camera projection mapped onto the curved surface. Normals and bounds are recomputed after deformation.

All three open-cylinder demo anomalies opt into `previewSurface: 'spherical'`, so the Main World, Poincare, and Hypercube-side mouths use the same three-dimensional cap treatment. The `flat` option remains the default for other/custom anomaly types unless their own `view` contract selects the spherical option. Rectangular spherical previews are rejected explicitly; a sphere cap is only defined for circular/elliptical aperture profiles in this implementation.

The surface's sagitta depth is configurable through `sphericalSagittaRatio` at the `PortalPreviewRenderer` level (default `0.38`, strictly between 0 and 1). Its final world/render dimensions follow the portal's authored width and height.

## 3. Legacy ring removal

The old torus rim was a decorative marker from the earlier flat-mouth presentation. Portal creation now constructs that torus only when an anomaly explicitly sets `showRim: true`. The default is `false`, and all three demo anomalies explicitly opt out. The portal surface itself supplies the mouth boundary; no redundant torus is created around it.

For compatibility, an anomaly may still request `showRim: true` where a decorative ring is desired. Generic torus-shaped demo props are unrelated scenery and are not removed.

## 4. Configuration example

```js
view: {
    enabled: true,
    mapping: 'endpoint-frame',
    apertureShape: 'circle',
    previewSurface: 'spherical',
    showRim: false,
    crossSection: 'euclidean-4d-ball',
    interiorBoundary: 'open-4d-cylinder',
    interiorBoundaryRadii: { source: 2.8, destination: 7.0 }
}
```

To retain the previous flat circular look, set `previewSurface: 'flat'`. To explicitly restore the legacy decorative ring, set `showRim: true`.

## 6. Known limitations and next refinement

- The current spherical surface is a concave spherical cap, not a complete interior sphere or a physically refracting lens.
- The spherical cap is currently supported for circular/elliptical aperture shapes. Rectangular spherical caps are intentionally unsupported.
- Cylinder boundary generation currently supports W-aligned anomaly axes only.
- The cylinder cross-section is evaluated in the current W slice; this milestone does not add arbitrary 4D surface intersections or optical occlusion inside the anomaly.
- Poincare/nonlinear slice projection can alter the rendered cap shape. This follows the active slice transform and should be judged in the live browser.
- A future in-tube destination surface may further improve the perceived distance/parallax, but should be a separately controlled render-only element and must not reintroduce a second aperture scale curve.
