D&D GRID REFINEMENT — CELL FORMATION, DASH, AND FLIGHT
============================================================
Implementation updated: November 6, 2026

CHARACTER PLACEMENT
-------------------
- Grid coordinates now resolve to cell centres, rather than grid-line intersections.
- A single character is placed at the exact centre of its cell.
- Characters sharing a cell are placed in a centered circular formation.
- Character models are scaled down as occupancy increases to keep horizontal model
  footprints separated and contained within the cell.

MOVEMENT AND ACTION ECONOMY
---------------------------
- Movement remains an independent per-turn resource.
- Normal movement does not consume an action or bonus action.
- Selecting a destination in the amber secondary movement region consumes the Dash
  action before movement is recorded.
- The Dash action doubles the movement allowance for that turn.
- Selecting Dash directly from the Action control also enables the doubled allowance.
- Spending a non-Dash action prevents later Dash movement for that turn.
- The preview refreshes after movement and after action use.

FLIGHT AND ALTITUDE
-------------------
- Character position records include `altitude`, measured above locally sampled terrain.
- Altitude is retained when a character moves between cells and is included in character
  serialization. Older saves without altitude default to zero.
- The tactical UI exposes altitude when creating a character and when editing a selected one.
- Rendered character roots are positioned at sampled terrain elevation plus altitude, through
  the existing SpatialTransform conversion.

STYLE REVIEW
------------
- Updated `docs/STYLE-CONFORMANCE.md` for every inspected/modified game source file and
  the new tactical regression test file.
- Removed anonymous callback expressions from the reviewed D&D mode, tactical UI, battle,
  and character modules.
- Decomposed movement, Dash validation, movement-preview range calculation, cell occupancy,
  grid-origin rollback, battle restoration, replay orchestration, constructor initialization,
  and character-mesh construction into named methods.
- Remaining long constructors, renderer algorithms, lifecycle methods, and DOM primitives
  remain recorded as future refactoring work rather than being broadly rewritten.

- Browser/Babylon.js verification remains outstanding for actual terrain projection, mesh
  overlap at different viewing angles, pointer picking on amber cells, altitude rendering,
